# ข้อกำหนดของโครงงาน PE104

เอกสารนี้สรุปว่าโปรแกรมของกลุ่มเราต้องทำอะไรบ้าง และต้องเตรียมอะไรเพื่อส่งอาจารย์

## 1. เป้าหมายของโครงงาน

สร้างโปรแกรมภาษา Python สำหรับทดลองวิเคราะห์หุ้นและความเสี่ยงจากการลงทุน โปรแกรมต้องใช้งานผ่าน Terminal ไม่ทำเป็นเว็บไซต์หรือหน้าต่าง GUI

## 2. วิธีใช้งานที่ต้องมี

- เปิดโปรแกรมจากโฟลเดอร์หลักด้วยคำสั่ง `python main.py` หรือ `python3 main.py`
- มีเมนูหลักและวนกลับมาแสดงเมนูจนกว่าผู้ใช้จะเลือก `0` เพื่อออก
- มีการรับข้อมูลจากผู้ใช้ และตรวจสอบว่ากรอกถูกต้องหรือไม่
- ถ้ากรอกผิด โปรแกรมต้องแจ้งเตือนและถามใหม่
- มีโหมดทดลองที่ใช้ข้อมูลตัวอย่างในเครื่องและไม่ต้องต่ออินเทอร์เน็ต

## 3. สิ่งที่ต้องมีในโค้ด

- ใช้ฟังก์ชันแบ่งงานให้ชัดเจน อย่างน้อย 6 ฟังก์ชันในภาพรวม
- ฟังก์ชันควรมี Docstring อธิบายว่าทำหน้าที่อะไร และใช้ `return` ส่งค่ากลับเมื่อต้องนำผลไปใช้ต่อ
- ใช้ List และ Dictionary รวมถึงข้อมูลแบบซ้อน เช่น List ที่เก็บ Dictionary หลายรายการ
- อ่านและเขียนไฟล์ เช่น CSV หรือ TXT
- ใช้ `try/except` เพื่อจัดการข้อผิดพลาด เช่น กรอกตัวเลขไม่ได้ หาไฟล์ไม่เจอ หรือข้อมูลในไฟล์ไม่ถูกต้อง
- ถ้าใช้ไลบรารีเพิ่มเติม ต้องบอกว่าใช้ทำอะไร

## 4. ความสามารถที่โปรแกรมต้องทำได้

1. อ่านหรือดาวน์โหลดราคาหุ้นย้อนหลัง
2. คำนวณผลตอบแทนรายวัน
3. คำนวณความผันผวนของหุ้น
4. จำลองผลการลงทุนด้วย Historical Bootstrap Monte Carlo
5. คำนวณโอกาสขาดทุน (Probability of Loss), VaR และ MDD
6. แสดงผลสรุปใน Terminal ให้อ่านง่าย
7. บันทึกรายงานเป็นไฟล์ข้อความ และเปิดรายงานเดิมได้

## 5. ไฟล์และเอกสารที่ต้องเตรียม

- `README.md` อธิบายโครงงาน วิธีติดตั้ง และวิธีใช้
- `main.py` เป็นไฟล์หลักของโปรแกรม
- `data_analysis.py`, `simulation.py`, `risk_report.py` เป็นไฟล์แยกตามหน้าที่
- `sample_data/stock_prices.csv` เป็นข้อมูลหุ้นตัวอย่าง
- `reports/risk_report.txt` เป็นรายงานที่โปรแกรมสร้าง
- `docs/requirements.md` สรุปข้อกำหนด
- `docs/test_plan.md` ตารางทดสอบและผลที่เกิดขึ้นจริง
- `docs/ai_log.md` บันทึกการใช้ AI
- `docs/lessons.md` สิ่งที่ได้เรียนรู้และแนวทางพัฒนาต่อ
- `docs/version_history.md` ประวัติการพัฒนา
- `demo_output.txt` ข้อความผลลัพธ์จากการรันจริง

## 6. สิ่งที่ต้องทดสอบก่อนส่ง

- ทดสอบอย่างน้อย 5 กรณี และควรทดสอบให้ครบตามตาราง
- ต้องมีกรณีกรอกข้อมูลผิด
- ต้องมีกรณีไฟล์หายหรือข้อมูลในไฟล์ไม่ถูกต้อง
- จดผลที่เห็นจริง ไม่เขียนผลขึ้นเอง
- บันทึกภาพหน้าจอประกอบการทดสอบ
- ตรวจสอบว่าไฟล์ข้อมูลตัวอย่างกลับมาเป็นข้อมูลปกติหลังทดสอบ

## 7. การใช้ AI และการเก็บเวอร์ชัน

- บันทึกว่าใช้ AI ช่วยเรื่องใด และตรวจสอบคำตอบอย่างไร
- ถ้า AI ให้คำตอบผิด ให้บันทึกข้อผิดพลาดและวิธีแก้ตามที่เกิดขึ้นจริง
- เก็บประวัติการเปลี่ยนแปลงของโค้ดผ่าน Git Commit อย่างน้อย 6 ช่วงการพัฒนา
- สมาชิกทุกคนควรเข้าใจโค้ดที่ตนเองรับผิดชอบและอธิบายการทำงานได้
