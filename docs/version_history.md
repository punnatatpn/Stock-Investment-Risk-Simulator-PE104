# ประวัติเวอร์ชันของโครงการ (Version History)

ประวัติ Commit ใน Git เป็นหลักฐานอ้างอิงหลักของเวอร์ชันโครงการ เอกสารนี้ไม่ได้สร้างสำเนาไฟล์เวอร์ชันเก่าที่ไม่เคยมีอยู่จริง แต่สรุปจุดเปลี่ยนสำคัญจากประวัติการบันทึกงานที่เกิดขึ้นจริง

| เวอร์ชัน / ช่วงการพัฒนา | Commit | รายละเอียดการเปลี่ยนแปลง |
|---|---|---|
| V1 – เริ่มต้นโครงการ | `87d08b48` | สร้างโครงงานและไฟล์พื้นฐาน |
| V2 – รวมระบบหลัก | `2258c1d1` | เชื่อมการวิเคราะห์หุ้น การจำลอง และรายงานความเสี่ยง |
| V3 – เมนูและโหมดสาธิต | `de15f690` | ปรับตัวเลือกออกจากโปรแกรมเป็น 0 และเพิ่มขั้นตอนสาธิตด้วยข้อมูลตัวอย่าง |
| V4 – คู่มือโครงการ | `19a3fc85` | เพิ่ม README วิธีใช้งาน หลักการคำนวณ และข้อจำกัด |
| V5 – ไลบรารีที่ต้องติดตั้ง | `7af7dd1d` | ระบุไลบรารี yfinance ที่โครงการต้องใช้ |
| V6 – เอกสารตามข้อกำหนด PE104 | `18d0d865`, `e3fcc111`, `2bde5931`, `b8b639bc` | เพิ่มเอกสารข้อกำหนด แผนทดสอบ บทเรียน และบันทึกการใช้ AI |
| V7 – จัดระเบียบ Repository | `325b3efd`, `812e64c9`, `9642daf2`, `b57b5852` | เพิ่มกฎการละเว้นไฟล์ที่ไม่จำเป็นและลบไฟล์ Bytecode ที่ถูกสร้างอัตโนมัติ |
| V8 – แยกแหล่งจัดเก็บข้อมูล | `7dfe64bb` | แยกข้อมูลที่ดาวน์โหลดจาก Yahoo Finance ไปเก็บใน data/cache แทน sample_data |

หากต้องการตรวจสอบเวอร์ชันที่บันทึกไว้ทั้งหมด ให้เปิด Repository บน GitHub แล้วเลือกเมนู **Commits** หรือใช้คำสั่ง `git log --oneline` ใน Terminal แต่ละ Commit จะเก็บสถานะของไฟล์ในช่วงเวลานั้นไว้ และสามารถเปรียบเทียบกับเวอร์ชันถัดไปได้

**หมายเหตุ:** รายการข้างต้นเป็นจุดเปลี่ยนจาก Git Commit จริง ไม่ใช่การสร้างไฟล์สำเนาเก่า 6 ชุดที่มีเนื้อหาเหมือนกัน ควรบันทึก Commit ใหม่ทุกครั้งที่มีการเพิ่มความสามารถหรือแก้ไขส่วนสำคัญ
